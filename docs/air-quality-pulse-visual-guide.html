Pipeline Flow

1. Source
OpenAQ or sample data
Public air-quality locations and latest pollutant readings.
2. Extract
Python runner
Loads one or many locations through API calls or sample payloads.
3. Raw
JSON files
Preserves original source responses for replay and debugging.
4. Transform
Clean and validate
Adds typed fields, metadata, quality flags, and safety labels.
5. Store
SQLite
Creates analytics-ready measurement and pipeline run tables.
6. Visualize
Streamlit
Shows filters, separate pollutant charts, map points, and guides.
Raw data and curated data are intentionally separate. That is the core habit: keep the source response, then build a cleaner analytics table from it.

Best Practices

Keep raw responsesDebug and replay without calling the API again.
Create curated tablesMake analytics easier than querying nested API JSON.
Use idempotent keysPrevent duplicate rows when the same reading is loaded again.
Log each runTrack row counts, source URLs, and load status.
Validate rowsCatch missing timestamps, invalid coordinates, and non-numeric readings.
Separate pollutant scalesPM2.5 and ozone use different units, so each needs its own plot.

Learning Outcomes

By the end of this project, you can explain not just the chart, but the engineering system behind it: where the data came from, how it was shaped, how it was checked, and why the visualization choices are trustworthy.
